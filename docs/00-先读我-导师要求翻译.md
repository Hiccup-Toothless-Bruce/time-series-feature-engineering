# 00 先读我：把导师的要求翻译成人话

## 1. 一句话看懂你的任务

导师给了你一份"时序数据集"，让你做**特征工程**。

说白了就是：

> 原始数据里只有一列时间，模型看不懂"2010-01-01 08:00"这种东西。
> 你要把它拆成"年=2010、月=1、日=1、小时=8、星期几、是不是周末"等数字，
> 再告诉模型"过去几小时发生了什么"（滞后、滑动窗口），
> 最后用实验证明：加了这些特征以后，预测有没有变好。

### 2.4 选一个目标，用线性回归跑基线

**人话**：先跑一个最笨的模型，作为以后对比的"地板"。

**本项目选的目标**：站在时间 t，用现在知道的信息，预测 t+1 时刻的 PM2.5。

**你要做**：运行 `python scripts\06_baseline_model.py`。

**怎么算完成**：能说出：

- 训练集是前 80%，测试集是后 20%；
- 为什么不能随机切分；
- MAE、RMSE、R² 分别是什么意思。

---

### 2.5 对小时、星期做正弦/余弦编码，观察效果变化

**人话**：直接给模型 `hour=23` 和 `hour=0`，它会觉得这两个数差得很远；
但现实中它们是挨着的。sin/cos 把时间放到一个圆上，让 23 点和 0 点变近。

**你要做**：运行 `python scripts\07_cyclic_encoding.py`，对比两行结果。

**怎么算完成**：能写出："在这个数据上，原始数字时间的 MAE = ____，周期编码的 MAE = ____，R² = ____。"

> 注意：不一定周期编码一定大幅更好。实验结论要写"在这个数据、这个模型、这段测试期上怎么样"，不要写"sin/cos 永远更好"。

### 3.1 做滞后和滑动窗口，体会不能混入未来数据

**人话**：

- 滞后（lag）：把过去的值挪到当前行，例如 `lag1` 是上一小时的值；
- 滑动窗口（rolling）：算过去 24 小时的平均值、标准差、最大值；
- 预测 t+1 时，只能用 t 及更早的数据，不能用 t+1 的数据。

**你要做**：运行 `python scripts\08_lag_rolling_features.py`。

**怎么算完成**：能指着表说出：对每一行，`lag1` 是哪个时刻、`roll24_mean` 用了哪些时刻、`pm25_next` 是哪个时刻。

## 3. 名词速查（先混个眼熟）

| 名词 | 一句话解释 | 例子 |
| --- | --- | --- |
| 时序数据 | 带时间戳、按时间排序的记录 | 每小时一条 PM2.5 |
| 时间戳 | 记录发生的具体时间 | 2014-01-01 08:00 |
| UTC | 世界统一时间，避免时区混乱 | 北京时间 = UTC+8 |
| 特征 | 喂给模型的输入列 | hour、is_weekend |
| 特征工程 | 从原始数据造出更有用的特征 | 把时间拆成小时和星期 |
| 周期 | 每隔一段时间重复出现的规律 | 一天、一周、一年 |
| 滞后 lag | 过去某个时刻的值 | `pm2.5.shift(1)` |
| 滑动窗口 rolling | 过去 N 个值的统计量 | 过去 24 小时平均 |
| 差分 diff | 当前值减上一个值 | 今天比昨天高多少 |
| 基线模型 | 最笨但必须有的对比模型 | 永远猜平均值 |
| 训练集 | 用来学习的旧数据 | 前 80% |
| 测试集 | 用来考试的新数据 | 后 20% |
| 数据泄漏 | 不小心把答案或未来信息喂给模型 | 用 t+1 的值预测 t+1 |
| MAE | 平均差多少，越小越好 | 10 表示平均差 10 |
| RMSE | 更重罚大错误的指标 | 也是越小越好 |
| R² | 拟合好不好的指标，1 最好 | 0 约等于只会猜平均 |

## 4. 整个项目的数据流

```text
原始 CSV
  ↓ download_data.py
带 year/month/day/hour 的原始表
  ↓ 04_load_clean.py：拼 UTC 时间、排序、检查缺失
干净的小时级数据（完整时间轴）
  ↓ 05_time_features.py：拆年/月/日/星期/小时/是否周末 + sin/cos
带时间特征的表
  ↓ 08_lag_rolling_features.py：shift + rolling + 目标 y
完整建模数据
  ↓ 09_model_comparison.py：按时间切分、训练线性回归、对比
实验表格 + 预测值
  ↓ 10_plots.py
6 张图
```
