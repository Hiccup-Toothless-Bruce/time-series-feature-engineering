## 核心 10 句话

1. 时序数据是带时间戳、按时间排好序的记录，**顺序本身就是信息**，不能随便打乱。
2. 时间戳统一用 **UTC**；北京时间 = UTC + 8。
3. 预测场景要先定义清楚：**站在 t 时刻，用截至 t 已知的信息，预测 t+1**。
4. 时间列可以拆成 **年、月、日、星期、小时、是否周末** 这些数字特征。
5. 小时、星期、月份用 **sin/cos 周期编码**，23 点和 0 点才会变成"邻居"。
6. **lag（滞后）** 是把过去的值挪到当前行：`shift(1)` 是上一小时，`shift(24)` 是昨天同一小时。
7. **rolling（滑动窗口）** 是算最近一段时间（如 24 小时）的均值、波动、最大最小值。
8. 任何用到了 t+1 及以后的信息，都是 **数据泄漏**，测试分数会假高。
9. 时序数据切分训练/测试必须 **按时间前后切**，不能随机切。
10. 先跑 **基线**（平均值、持续法），再谈复杂模型；指标看 **MAE、RMSE、R²**。

# 3. 时间戳处理

对应脚本：`scripts/04_load_clean.py`；对应教程：`docs/04-时序特征工程核心.md`。

## 3.1 拼出 UTC 时间列

```python
import pandas as pd

dt = pd.to_datetime(df[["year", "month", "day", "hour"]])
df["datetime"] = dt.dt.tz_localize("UTC")
```

**作用**：

- 原始数据把时间拆成 4 列存，这一步把它们拼成一个带时区的时间列。
- `tz_localize` 的意思是"这些数字本来就是 UTC 时间"；如果原始时间是北京时间，就要先 `tz_localize("Asia/Shanghai")` 再 `tz_convert("UTC")`。
- 统一 UTC 是为了避免"两份数据一个用北京时间、一个用 UTC，合并后差 8 小时"。

## 3.2 排序 + 补齐完整时间轴

```python
df = df.set_index("datetime").sort_index()
df = df.asfreq("h")          # 保证每个整点都有一行，缺的补成 NaN

expected = pd.date_range(df.index.min(), df.index.max(), freq="h")
print(len(expected), len(df), len(expected) - len(df))   # 应该有 / 实际有 / 缺多少
```

**作用**：

- `asfreq("h")` 让"每隔一小时一行"变成硬约束。
- 为什么必须补：如果不补，`shift(24)` 表示的是"往前数 24 行"，而不是"24 小时前"，遇到缺口就会错位，`rolling(24)` 也一样。

## 3.3 缺失值：短缺口插值，长缺口保留

```python
df["pm25_was_missing"] = df["pm2.5"].isna().astype(int)   # 留个标记，方便以后分析
df["pm2.5"] = df["pm2.5"].interpolate(method="linear", limit=6, limit_direction="both")
```

**作用**：

- 连续缺失不超过 6 小时 → 用前后值线性插值补上（相邻小时污染水平接近，这样猜比较合理）。
- 连续缺失很久 → 保留 NaN，不硬猜；建模时按用到的特征删掉这些行。
- 插值也是"猜"，必须在报告里写清楚处理方式，不能装作数据本来没有缺失。

## 3.4 时区换算（要看北京作息时）

```python
df["hour_beijing"] = (df["hour"] + 8) % 24                      # 简便算法
df["datetime_beijing"] = df.index.tz_convert("Asia/Shanghai")   # 正规做法
```

**作用**：

- 本项目统一用 UTC 讲解；UTC 08:00 = 北京 16:00。
- 想研究"北京早高峰"，就加上 `hour_beijing` 这一列再分组看。

# 4. 时间特征

对应脚本：`scripts/05_time_features.py`。

## 4.1 日历特征

```python
index = df.index
df["year"] = index.year
df["month"] = index.month
df["day"] = index.day
df["hour"] = index.hour
df["dayofweek"] = index.dayofweek          # 0=周一, 6=周日
df["is_weekend"] = (index.dayofweek >= 5).astype(int)
df["dayofyear"] = index.dayofyear
```

**作用**：

- 把"时间戳"翻译成模型看得懂的数字：年看长期趋势，月看季节，小时看早晚高峰。
- `day`（几号）通常用处不大，容易让模型记住偶然现象（过拟合），可以先不加。
- `is_weekend` 是最直观的一个：工作日和周末的规律常常不一样。

## 4.2 星期几的可读版本

```python
WEEKDAY_NAMES = ["周一", "周二", "周三", "周四", "周五", "周六", "周日"]
df["weekday_name"] = df["dayofweek"].map(lambda x: WEEKDAY_NAMES[x])
```

**作用**：给人看的列，画图、写报告时比 0~6 直观；建模时用 `dayofweek` 数字列。

## 4.3 周期编码：sin/cos

```python
import numpy as np

df["hour_sin"] = np.sin(2 * np.pi * df["hour"] / 24)
df["hour_cos"] = np.cos(2 * np.pi * df["hour"] / 24)

df["dayofweek_sin"] = np.sin(2 * np.pi * df["dayofweek"] / 7)
df["dayofweek_cos"] = np.cos(2 * np.pi * df["dayofweek"] / 7)
```

**作用**：

- 直接给模型 `hour=23` 和 `hour=0`，模型会以为它们差 23；放到圆上以后，它俩其实是邻居。
- 除以周期长度（24 小时、7 天、12 个月），再用 sin/cos 算出圆上的横纵坐标，两个数配对表示一个位置。
- 月份编码写 `(month - 1) / 12`，是为了让 1 月从 0 开始，跟其他周期的写法一致。

## 4.4 观察周期性

```python
by_hour = df.groupby("hour")["pm2.5"].mean()
by_weekday = df.groupby("weekday_name")["pm2.5"].mean().reindex(WEEKDAY_NAMES)
```

**作用**：分组求平均，看看"哪个小时更脏、哪一天更脏"。柱子高低差别明显，就说明时间特征有用。

# 5. 滞后与滑动窗口

对应脚本：`scripts/08_lag_rolling_features.py`。

## 5.1 lag：把过去的值挪到当前行

```python
df["pm25_now"] = df["pm2.5"]        # 当前时刻的值（可以立刻测到，能用）
df["pm25_lag1"] = df["pm2.5"].shift(1)      # 上一小时
df["pm25_lag2"] = df["pm2.5"].shift(2)      # 上两小时
df["pm25_lag24"] = df["pm2.5"].shift(24)    # 昨天同一小时
df["pm25_lag168"] = df["pm2.5"].shift(168)  # 上周同一小时（7×24）
```

**作用**：

- `shift(1)` 把整列往下挪一格，于是"上一小时的值"出现在当前行，可以当作特征。
- 污染物有明显惯性，`lag1`、`lag24` 通常是最有用的特征。
- 挪完前几行会出现 NaN，这是正常的，最后 `dropna` 掉即可。

## 5.2 diff：变化量

```python
df["pm25_diff1"] = df["pm2.5"].diff(1)     # 比上一小时高/低了多少
df["pm25_diff24"] = df["pm2.5"].diff(24)   # 比昨天同一小时高/低了多少
```

**作用**：`diff` 相当于"当前值 − 之前的值"，描述的是趋势和变化速度，对突变更敏感。

## 5.3 rolling：滑动窗口

```python
window24 = df["pm2.5"].rolling(window=24, min_periods=18)

df["pm25_roll24_mean"] = window24.mean()   # 最近 24 小时平均
df["pm25_roll24_std"] = window24.std()     # 最近 24 小时波动
df["pm25_roll24_max"] = window24.max()     # 最近 24 小时最高
df["pm25_roll24_min"] = window24.min()     # 最近 24 小时最低

df["pm25_roll168_mean"] = df["pm2.5"].rolling(window=168, min_periods=120).mean()  # 最近 7 天
```

**作用**：

- 默认窗口在当前时刻结束（trailing），里面全是过去的值，预测下一小时时是安全的。
- `min_periods=18` 表示"24 小时里至少有 18 个有效值才算"，既不会被个别缺失整行丢掉，也不会只靠一两个值硬算平均。
- `mean` 看水平、`std` 看稳定程度、`max/min` 看极端情况。

## 5.4 目标：下一个小时的值

```python
df["pm25_next"] = df["pm2.5"].shift(-1)    # 向上挪一格 = 下一小时的值
df = df.dropna(subset=["pm25_next"])       # 最后一行没有下一小时，删掉
```

**作用**：

- 这一列是**答案（y）**，只能用来训练和打分，绝不能出现在特征列里。
- `shift(-1)` 和 `shift(1)` 方向相反：负数 = 未来，正数 = 过去。

## 5.5 时间对齐：一张表看懂谁对应谁

| 列名 | 对应时刻 | 说明 |
| --- | --- | --- |
| `pm2.5` | t | 当前小时测得的值 |
| `pm25_lag1` | t-1 | 上一小时 |
| `pm25_lag24` | t-24 | 昨天同一小时 |
| `pm25_roll24_mean` | t-23 ~ t | 最近 24 小时的平均 |
| `pm25_next` | t+1 | 要预测的答案 |

**作用**：写代码时随时回看这张表，就不容易把未来信息混进特征（这是最常见的错误）。

```python
features = ["month", "day", "hour", "dayofweek", "is_weekend", "dayofyear"]

x_train = train[features]      # 特征（问题）
y_train = train["pm25_next"]   # 目标（答案）
```

**作用**：

- 建模就是把"能知道的信息"（X）和"要预测的答案"（y）分清楚。
- 特征必须满足一个条件：**在预测时刻已经能拿到**。

## 6.2 按时间切分训练集/测试集

```python
split_index = int(len(df) * 0.8)
train = df.iloc[:split_index].copy()     # 前 80%：训练
test = df.iloc[split_index:].copy()      # 后 20%：测试
```

**作用**：

- 时序数据必须"用过去训练、拿未来测试"，模拟真实预测场景。
- 随机切分会让未来信息混进训练集，分数虚高（第 7 章有真实数字对比）。

## 6.3 基线模型：先跑简单的

```python
from sklearn.dummy import DummyRegressor

dummy = DummyRegressor(strategy="mean")   # 永远预测训练集的平均值
dummy.fit(x_train, y_train)
dummy_pred = dummy.predict(x_test)

persistence_pred = test["pm25_now"].to_numpy()   # 持续法：下一小时 = 当前小时
```

**作用**：

- 平均值基线：什么都不学，只猜平均值，用来当"最低标准"。
- 持续法：直接说"下一小时和现在差不多"。在污染物、股价这类有惯性的数据上，它往往很强。
- 复杂模型如果打不过这两个基线，说明特征或方法有问题。

## 6.4 线性回归

```python
from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(x_train, y_train)      # 训练
pred = model.predict(x_test)     # 预测

for name, coef in zip(features, model.coef_):
    print(name, round(coef, 4))  # 看每个特征的系数
```

**作用**：

- 线性回归就是给每个特征学一个权重，然后加权求和。
- 系数正负表示方向（正 = 越大越容易高），但系数大小受量纲影响，不能直接当重要性排名；想比较大小要先标准化。

## 6.5 标准化后再看系数

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
x_train_scaled = scaler.fit_transform(train[features])
x_test_scaled = scaler.transform(test[features])     # 注意：用训练集的规则去转换测试集

model = LinearRegression().fit(x_train_scaled, y_train)
```

**作用**：把所有特征缩放到可比的尺度，系数大小才能横向比较（本项目输出到 `09_feature_coefficients.csv`）。

## 6.6 三个指标怎么读

```python
mae = np.mean(np.abs(y_true - y_pred))                    # 平均差多少
rmse = np.sqrt(np.mean((y_true - y_pred) ** 2))           # 更重罚大错
r2 = 1 - np.sum((y_true - y_pred) ** 2) / np.sum((y_true - y_true.mean()) ** 2)
```

**作用**：

- **MAE**：平均每次预测差多少，最好和 PM2.5 本身的平均值一起看（本数据平均约 80~100，MAE 11 就不错）。
- **RMSE**：和 MAE 类似，但对离谱的大错误更敏感。
- **R²**：1 最好；0 约等于"只会猜平均值"；负数说明比猜平均值还差。

## 6.7 实验怎么写

```text
实验名 | 用了哪些特征 | 切分方式 | MAE | RMSE | R² | 是否可信
```

**作用**：

- 一次只改一处，其他保持不变，这样的对比才有意义（控制变量）。
- 表里一定要标出"是否可信"，把泄漏实验单独区分开（项目里已有这张表：`outputs/tables/09_model_comparison.csv`）。

# 7. 数据泄漏：三种错误示范

对应脚本：`scripts/08_lag_rolling_features.py`、`scripts/09_model_comparison.py`。

## 7.1 中心滑动窗口（看了未来）

```python
# 错误：center=True 表示窗口中心在当前行，会包含 t+1、t+2 的未来值
df["pm25_roll24_mean_center_leaky"] = df["pm2.5"].rolling(window=24, center=True, min_periods=24).mean()
```

**作用/后果**：预测下一小时时却用了后面几小时的信息。分数会变好，但这个"好"是假的。

## 7.2 把答案当特征（最离谱的作弊）

```python
df["pm25_answer_leaky"] = df["pm25_next"]     # 严重错误：答案直接变成特征
```

**作用/后果**：模型等于抄答案，R² 会到 1.0000、MAE 会到 0。看到"完美分数"先怀疑泄漏，而不是高兴。

## 7.3 随机切分（考试漏题）

```python
# 错误做法：时序数据不要这样切
x_train, x_test, y_train, y_test = train_test_split(x, y, test_size=0.2, random_state=42)
```

**作用/后果**：随机切分会把"未来"混进训练集，测试分数虚高（本项目对比：随机切分 R² 0.9494，按时间切分 0.9426，看起来更好，但不可信）。

## 7.4 防泄漏检查清单

- [ ] 每一列特征，在预测时刻 t 都拿得到吗？（拿不到就删）
- [ ] 有没有 `center=True`？有就改成默认的 trailing 窗口。
- [ ] 有没有列名带 `next`、`answer`、`leaky` 却出现在 `features` 里？
- [ ] 是在排序 + 补齐时间轴之后才算的 `shift`/`rolling` 吗？
- [ ] 训练集时间是否完全早于测试集？
- [ ] 分数好得反常（R²>0.99）时，是否停下来查一遍泄漏？

# 9. SQLite 数据库

对应脚本：`scripts/03_sqlite_basics.py`。Python 自带，零配置。

## 9.1 连接与建表

```python
import sqlite3

conn = sqlite3.connect("data/processed/practice.db")
conn.execute("""
    CREATE TABLE IF NOT EXISTS weather_notes (
        id    INTEGER PRIMARY KEY,   -- 主键：唯一身份证，不能重复
        city  TEXT NOT NULL,
        date  TEXT NOT NULL,
        temp  REAL,
        note  TEXT
    )
""")
conn.commit()
```

**作用**：

- SQLite 把整个数据库存成一个 `.db` 文件，不用装服务器，适合练习和小项目。
- `PRIMARY KEY` 保证每行有唯一 id；`NOT NULL` 表示这列不能空着。
- 类型：`INTEGER` 整数、`TEXT` 文本、`REAL` 小数。

## 9.2 增删改查

```python
# 增：? 是占位符，防止拼字符串出错（也能防注入）
conn.executemany(
    "INSERT OR REPLACE INTO weather_notes (id, city, date, temp, note) VALUES (?, ?, ?, ?, ?)",
    [(1, "Nanjing", "2026-10-01", 28.0, "sunny")],
)

# 查
conn.execute("SELECT * FROM weather_notes WHERE city = ? ORDER BY id", ("Nanjing",))
conn.execute("SELECT city, COUNT(*) AS n FROM weather_notes GROUP BY city ORDER BY n DESC")

# 改
conn.execute("UPDATE weather_notes SET temp = ?, note = ? WHERE id = ?", (29.5, "updated", 1))

# 删
conn.execute("DELETE FROM weather_notes WHERE id = ?", (4,))

conn.commit()    # 增删改之后一定要 commit
conn.close()     # 用完关掉
```

**作用**：

- `SELECT` 查、`INSERT` 增、`UPDATE` 改、`DELETE` 删 —— 数据库的四个基本动作。
- `WHERE` 决定动哪几行；**忘了写 WHERE，UPDATE/DELETE 会作用到整张表**，务必先 `SELECT` 确认。

## 9.3 主键与索引

```python
conn.execute("CREATE INDEX IF NOT EXISTS idx_weather_city ON weather_notes (city)")
```

**作用**：

- 主键：自动唯一，插入重复 id 会直接报 `IntegrityError`（这是好事，数据更安全）。
- 索引：像书的目录，让"按 city 查询"更快；代价是占空间、写入稍慢，只给常用查询列建。

# 10. 报错急救

对应教程：`docs/99-报错急救.md`。

| 报错信息（关键部分） | 原因 | 怎么解决 |
| --- | --- | --- |
| `python 不是内部或外部命令` | 没装 Python 或没勾选 Add to PATH | 重新安装 Python 并勾选 Add Python to PATH；或用 `py` 命令 |

| `FileNotFoundError: ... pm25_clean.csv` | 上一个脚本没跑 | 按顺序跑 04 → 05 → 06…，或直接 `.\run_all.ps1` |
| `KeyError: 'hour'` | 列名不存在/拼错，或少了上一步生成的特征 | 用 `df.columns` 看真实列名；确认跑过 05/08 |
| `ValueError: could not convert string to float` | 该是数字的列里混了文字/空值 | `df["列"].head()` 看看内容；必要时 `pd.to_numeric(errors="coerce")` |
| `TypeError: unsupported operand type(s)` | 字符串当数字算了 | 检查这列的 `dtype`（`df.dtypes`），先转换类型 |
| `SettingWithCopyWarning` | 在切片副本上改数据 | 先 `.copy()`，再赋值：`part = df.iloc[:100].copy()` |
| `UnicodeDecodeError: 'utf-8' codec can't decode` | 文件不是 UTF-8（常见 GBK） | 读的时候加 `encoding="gbk"`；写 CSV 用 `utf-8-sig` |
| CSV 用 Excel 打开中文乱码 | 编码不是 Excel 认的格式 | 保存时用 `encoding="utf-8-sig"` |
| matplotlib 中文变方框 | 没设置中文字体 | 加 `plt.rcParams["font.sans-serif"] = ["Microsoft YaHei"]` |
| 服务器提示端口被占用 | 8765 已被别的程序占用 | 换端口：`start-server.ps1 -Port 8899` |
| Git `fatal: not a git repository` | 当前目录还不是仓库 | 在项目根目录先 `git init` |
| Git `failed to push` / 要登录 | 远端仓库或凭据问题 | `git remote -v` 检查地址；按提示登录 GitHub |
| `PermissionError: [Errno 13]` | 文件被 Excel 等程序占用 | 关掉正在打开的文件再运行脚本 |

**通用排查三步**：

1. 看报错**最后一行**（错误类型 + 原因），再看它指出的是哪个文件哪一行。
2. 打开那个文件、找到那一行，想想这一行需要什么（列？文件？库？）。
3. 还没头绪就把整段报错复制去搜索，或者把"最后一行 + 代码那几行"发给同学/导师。
